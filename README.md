# MetaWorld MT50 task-label repair

This tool addresses the MetaWorld MT50 `push-back-v3` task-label collision
reported in
[huggingface/lerobot#4409](https://github.com/huggingface/lerobot/issues/4409).
It prepares local repair files for
[`lerobot/metaworld_mt50`](https://huggingface.co/datasets/lerobot/metaworld_mt50),
changing task ID 37 from task index 40 to 49 while keeping task ID 38 on
index 40.

## Reproduction

The repair targets the pinned `lerobot/metaworld_mt50` dataset revision
`a59f742d218c903328164257ecf180f9b18018a1`. Clone the LeRobot repository,
check out revision `73ab890324b303424a8a5f07272f22c36be5d269`, and then
clone this repair tool separately. Run the tool with Python 3.12 or newer:

```bash
git clone https://github.com/huggingface/lerobot.git
cd lerobot
git checkout --detach 73ab890324b303424a8a5f07272f22c36be5d269

uv sync --locked --extra dataset --extra test

git clone https://github.com/tc-huang/metaworld_mt50_repair.git

uv run --locked python -m metaworld_mt50_repair.reproduce \
  --output ./metaworld_mt50_repair_output
```

`reproduce` downloads the required files from the pinned revision, creates the
replacement files, and runs the complete validation. `--output` must point to a
new directory outside the source snapshot.

### Tool layout

```text
metaworld_mt50_repair/
├── README.md
├── download.py
├── repair.py
├── repair_manifest.json
├── reproduce.py
├── validate.py
└── tests/
    ├── test_repair.py
    └── test_validate.py
```

- `download.py`: Downloads the dataset revision specified by
  `repair_manifest.json` and skips video files.
- `repair.py`: Checks the source dataset and creates replacement data Parquets,
  metadata, and the dataset card.
- `validate.py`: Compares the replacement files with the source snapshot and
  verifies the change scope, statistics, hashes, and provenance.
- `reproduce.py`: Runs download, repair, and validation in sequence through one
  reproduction entry point.
- `repair_manifest.json`: The tool's input manifest. It pins the source
  repository, revision, data-file count, frame count, and episode count. It has
  a different purpose from the audit manifest with the same name generated by
  `repair.py` in the output directory.
- `tests/`: Tests the success and rejection conditions of repair and validation
  separately, so the two implementations do not validate each other.
- `README.md`: Usage and repair documentation.

### Input `repair_manifest.json`

```json
{
  "source_repo_id": "lerobot/metaworld_mt50",
  "source_revision": "a59f742d218c903328164257ecf180f9b18018a1",
  "data_files": 492,
  "total_frames": 204806,
  "total_episodes": 2500
}
```

- `source_repo_id`: The Hugging Face dataset repository to repair.
- `source_revision`: The immutable dataset commit hash to download and repair.
- `data_files`: The expected number of data Parquets in the source snapshot.
- `total_frames`: The expected total number of frames in the source dataset.
- `total_episodes`: The expected total number of episodes in the source
  dataset.

`download.py` downloads the specified snapshot using the repository and
revision. Before writing any files, `repair.py` verifies that all three dataset
size fields match. The repair stops if any value differs from the source
dataset. The input manifest does not record the number of affected files or
modified rows. The tool derives those results from the source frames and writes
them to the audit manifest with the same name in the output directory.

## Repair procedure

`repair.py` first verifies that the source snapshot matches the known task-label
collision. It then creates replacement files in this order:

1. `data/**/*.parquet`: Finds data Parquets containing `task_id=37` and changes
   only those rows from `task_index` 40 to 49. All other columns and rows remain
   unchanged. The pinned revision has 22 affected data Parquets, but the tool
   derives the actual number from the data instead of hard-coding it.
2. `meta/tasks.parquet`: Adds the missing task instruction
   `Push the puck back toward the robot to the goal` with `task_index=49`.
   Existing tasks and task indices remain unchanged.
3. `meta/episodes/chunk-000/file-000.parquet`: Changes the instruction for the
   episodes belonging to task ID 37 from `Push the puck to a goal` to the new
   push-back instruction. It also changes the per-episode `task_index` minimum,
   maximum, and mean from 40 to 49. The standard deviation, count, and all other
   episode metadata remain unchanged.
4. `meta/info.json`: Changes only `total_tasks` from 49 to 50.
5. `meta/stats.json`: Recomputes and replaces the `task_index` minimum, maximum,
   mean, standard deviation, and count from the repaired frame-level task
   indices. All other feature statistics remain unchanged.
6. `README.md`: Changes only the embedded dataset-card value `"total_tasks": 49`
   to `"total_tasks": 50`.
7. `repair_manifest.json`: After all replacement files are complete, records
   the source identity, measured repair size, runtime and tool versions, and the
   before and after SHA-256 hashes of every file. This manifest is only for local
   validation and must not be uploaded with the dataset pull request.

At the pinned revision, the output contains 22 data Parquets and five metadata
files, for a total of 27 replacement files to upload.

### Output layout

Using the example output path above, `reproduce` creates the following
directory. The listed data Parquet filenames are the result for the pinned
revision. The tool still discovers the affected files from the data:

```text
metaworld_mt50_repair_output/
├── data/
│   └── chunk-000/
│       ├── file-403.parquet
│       ├── ...
│       └── file-424.parquet
├── meta/
│   ├── episodes/
│   │   └── chunk-000/
│   │       └── file-000.parquet
│   ├── info.json
│   ├── stats.json
│   └── tasks.parquet
├── README.md
└── repair_manifest.json
```

Together, `data/`, `meta/`, and `README.md` contain the 27 replacement files.
Their paths match the files they replace in the dataset repository. The
additional `repair_manifest.json` is a local audit file used by `validate.py` to
verify the source, provenance, and hashes. Do not upload it with the dataset
pull request.

## Individual steps

Use these commands to run or diagnose download, repair, and validation
separately:

```bash
uv run --locked python -m metaworld_mt50_repair.download
uv run --locked python -m pytest -q metaworld_mt50_repair/tests
uv run --locked python -m metaworld_mt50_repair.repair --source SOURCE --output OUTPUT
uv run --locked python -m metaworld_mt50_repair.validate --source SOURCE --output OUTPUT
```

`download.py` creates a `LeRobotDataset` from the pinned source repository and
revision, skips video files, and prints the resolved snapshot path. Pass that
path as `SOURCE`.

## Create a dataset pull request

The replacement directory contains only the changed data Parquets and five changed metadata files, for a total of 27 files at the pinned revision. Do not upload the
generated `repair_manifest.json`.

```bash
hf auth login

TARGET_REPO=lerobot/metaworld_mt50
OUTPUT=./metaworld_mt50_repair_output
COMMIT_DESCRIPTION="Resolve the task-label collision reported in
https://github.com/huggingface/lerobot/issues/4409 by moving task_id=37
from task_index=40 to 49 while keeping task_id=38 on task_index=40.

This repair relabels 8,888 frames in 50 episodes across 22 data
Parquets. It also aligns the task registry, episode metadata,
dataset-level task-index statistics, total task count, and dataset card.

Thanks to @sawhney17 for documenting the issue in detail and proposing
the repair in https://github.com/huggingface/lerobot/issues/4409."

HF_XET_HIGH_PERFORMANCE=1 hf upload "$TARGET_REPO" "$OUTPUT" . \
  --repo-type dataset \
  --exclude "repair_manifest.json" \
  --commit-message "Fix MetaWorld MT50 push-back task metadata" \
  --commit-description "$COMMIT_DESCRIPTION" \
  --create-pr
```
